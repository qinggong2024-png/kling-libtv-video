## 分层验收口径

此前将核心安全不变量、隔离增强证据和真实发布验收混为一个门槛，导致未授权的真实供应商/正式环境试验被错误地当作 G1 核心失败。现按以下口径执行：

- **G1-Core（必须通过）**：未知付费提交不重投/不退款/不切换供应商；原供应商轮询、下载、结算保留；幂等、额度、取消、结算和并发竞态受保护；公开回调默认拒绝；API/Runner 崩溃恢复、用户隔离和受控审计成立；测试分支与 `main` 的同范围证据一致。
- **G1-Conditional（隔离增强）**：CLI 进程崩溃、后台下载中断、PostgreSQL 变体、SSE 快照重连、前端部分刷新、指标契约和完整脱敏清单。单项未完成必须显式记录，不得覆盖 Core 失败。
- **Release Readiness（另行批准）**：真实供应商账单/任务生命周期、真实媒体质量、浏览器网络断线、生产观察窗口、部署重启和回滚。需要明确账号、费用上限、次数上限、停止条件和批准人；当前未授权、未执行。

分层只改变报告边界，不降低安全不变量。G1-Core 通过也不代表生产发布批准。

## 结论与边界

所选用例通过不等于安全矩阵全部通过。上述测试可使用隔离假Provider和故障注入，不以付费API授权作为一般阻塞理由。回调认证须有经确认的供应商或受控网关协议，不能自行编造请求头。G1仍待验收，不进入G2。
