# 固定模板视频生产工作台改造指令（当前仓库适配版）

版本：1.0-draft
适用仓库：`C:\Users\Reel\Documents\libtv自动化生成`
技术栈：FastAPI + SQLAlchemy/Alembic + React/Vite + 独立 Runner
改造依据：`F:\download\固定模板视频生产工作台改造指令.txt`

## 一、已确认的产品决策

1. 新的固定模板视频主流程只使用 Kling 官方 CLI。
2. 用户点击“开始生成”即代表确认本次付费提交。
3. 正常任务不调用 GPT 视觉分析，不等待 GPT 编写提示词。
4. 用户输入为 1–7 张已经确认的有序分镜图，不再要求产品参考图。
5. 首批模板为：
   - `ootd_walk`
   - `garment_detail`
   - `mood_model`
6. 默认每个父任务生成 1 条视频，可选择生成 1–4 条。
7. 新任务不再使用“稳定版/动态版”作为业务维度。
8. 历史 LibTV 任务和历史 `STABLE/DYNAMIC` 任务继续可查询、播放、下载和恢复。
9. LibTV、OpenAI 分析及旧 A/B 流程作为兼容能力保留，但不进入新制作首页的默认路径。
10. 用户后续提供的近期生产提示词是三个正式模板的主要内容来源；接入前需要拆解、去事实复述、结构化并补充约束。

## 二、不可照搬原指令的部分

原指令按单文件 Node 项目设计，本仓库已有更成熟的工程基础，不进行以下降级：

- 不把 FastAPI 后端改成 Node `server.js`。
- 不使用 `data/tasks.json` 代替 SQLAlchemy 数据库。
- 不使用浏览器 `Data URL` 持久化素材。
- 不用 Node 内置测试替代 Pytest/Vitest。
- 不重新实现已存在的 Kling 官方 CLI 适配器。
- 不删除现有 Runner、幂等、积分预留、审计、熔断、恢复和下载校验机制。
- 不伪造 Kling API endpoint 或未经实时能力声明确认的参数。

## 三、目标用户流程

```text
上传 1–7 张有序分镜图
→ 选择固定模板
→ 选择生成数量
→ 可选调整动作强度、镜头节奏和切镜方式
→ 点击“开始生成”（同时确认本次付费提交）
→ 后端确定性校验
→ 后端模板编译
→ 创建 1–4 个生成子任务
→ Runner 通过 Kling 官方 CLI 提交
→ 持久化 generationId 并轮询
→ 下载和 ffprobe 技术检查
→ 自动交付或进入“需要处理”
```

正常路径必须满足：

- GPT 视觉调用次数为 0。
- 不出现“分析素材”“AI 识图”“方案确认”和逐张人工审核。
- 不要求用户查看或编辑完整提示词。
- HTTP 请求不等待视频生成完成。
- 下载失败只重新下载，不重新提交生成。

### 5.1 父任务新增字段

在兼容历史数据的前提下，为 `ParentTask` 增加：

```text
workflow_kind             FIXED_TEMPLATE | LEGACY_ANALYSIS
template_id               nullable for historical rows
template_version          nullable for historical rows
```

新任务的 `workflow_kind` 固定为 `FIXED_TEMPLATE`。

### 5.2 生成结果

为 `GenerationVariant` 增加通用编号：

```text
variant_index     1..4
variant_key       deterministic stable key
variant_seed_json 本变体允许变化的动作/运镜组合
```

历史 `variant_type=STABLE/DYNAMIC` 保留。新代码读取时：

- 有 `variant_index`：显示“结果 1–4”。
- 无 `variant_index`：按历史 A/B 方式显示。

### 5.3 设置

```json
{
  "variantCount": 1,
  "actionIntensity": "standard",
  "cameraTempo": "standard",
  "cutMode": "explicit_cuts",
  "durationSeconds": 10,
  "ratio": "9:16",
  "sound": false,
  "subtitles": false,

```

其中 `durationSeconds`、`ratio`、`sound` 和 `smartStoryboard` 必须在提交前与实时
Kling 模型能力交叉校验。无法兑现时在扣费前阻止任务，不得静默忽略。

## 六、图片语义

“图片原样交给 Kling”的定义为：

- 不使用 GPT 重新描述图片事实；
- 不自动重绘、换衣或生成候选图片；
- 不改变用户确认的顺序；
- 允许为文件安全、EXIF 方向和 Provider 格式限制生成规范化副本。

上传时同时保留：

- 原始文件对象；
- 原始 SHA-256；
- 文件大小和原始 MIME；
- 规范化生成副本；
- 规范化副本 SHA-256、宽高和 MIME；
- 缩略图。

Provider 默认使用满足实时合同的规范化副本。原始文件用于审计和未来恢复。

## 七、确定性素材校验

新增 `MaterialValidator`，不得调用 GPT。

检查：

- 分镜数量 1–7；
- 顺序从 1 连续开始；
- MIME/文件魔数；
- 文件大小和空文件；
- 图片可解码；
- 最小/最大尺寸；
- 重复原始或规范化 SHA-256；
- 模板存在；
- 模板图片数量兼容；
- 生成数量 1–4；
- 设置枚举合法；
- 当前 Kling 模型输入数量和参数能力。

输出：

```json
{
  "valid": true,
  "errors": [],
  "warnings": [],
  "visionCheckRequired": false
}
```

V1 中 `visionCheckRequired` 只作为可选智能检查提示，不自动调用 GPT。

## 八、固定模板与提示词编译

模板放在：

```text
backend/src/libtv_agent/templates/video_templates.py
```

编译器放在：

```text
backend/src/libtv_agent/services/prompt_compiler.py
```

模板内容必须拆成：

- opening
- middle
- ending
- action presets
- camera presets
- tempo presets
- cut rules
- invariants
- negatives
- variant-safe differences

编译输入只包含模板、分镜数量、固定设置和 `variantIndex`，不得包含 GPT 生成的图片描述。
站点调研接入后，编译输入再增加已版本化的 `siteStyleProfile`；站点风格只能控制动作表达、
景别、节奏、运镜和商品表达倾向，不得重写人物与服装事实。

### 8.1 站点风格层（2026-07-30 已落地研究版）

- 研究文档：`docs/站点视频风格调研_2026-07-30.md`
- 配置注册：`backend/src/libtv_agent/templates/site_style_profiles.py`
- 原子动作库：`backend/src/libtv_agent/templates/motion_actions.py`
- 查询接口：`GET /api/v1/site-style-profiles`
- 编译器输入已支持可选 `site_profile`，并记录 `siteProfileId/siteProfileVersion`。
- 动作 ID 必须先经过视频模板兼容矩阵，再渲染为自然语言；例如细节模板不能因为站点偏好而自动加入走动或夸张姿态。
- 8 个 profile 当前均为 `draft`。NerdyWave、PageWings、GoodNurseLife 因站点 403 标为 `restricted_site`，不能把暂定风格当作已验证事实。
- 站点层不会读取图片内容，不触发 GPT，也不能新增人物、服装、道具或场景事实。

### 8.2 当前真实接入状态

截至 2026-07-30，模板注册、素材确定性校验、站点风格注册、动作兼容过滤和提示词编译已经具备；制作首页和现有 `POST /api/v1/tasks` 仍然是历史分析流程，尚未切换到固定模板付费主流程。

因此当前系统必须继续满足以下限制：

- 不得把“存在模板/profile 查询接口”表述为新主流程已完成。
- 不得让制作首页选择 draft 模板后进入历史 `ANALYZING`。
- 不得为了临时打通而复用旧 `confirm` 接口伪装成一键付费提交。
- 下一实现单元必须是独立 `POST /api/v1/video-tasks`，在同一事务中完成确定性校验、版本快照、提示词编译、1～4 个通用 variant 创建和付费授权时间记录；随后由 Runner 的 Kling-only 分支消费。
- 在模板/profile 未激活或实时 Kling 能力不匹配时，`POST /api/v1/video-tasks` 必须在扣费和 provider 提交前返回明确错误。

编译输出包含：

```text
templateId
templateVersion
masterPrompt
shotInstructions
invariants
negativePrompt
variantSeed
```

变体只允许改变动作幅度、有限动作组合、镜头节奏和有限运镜方式，不得改变人物和服装事实。

用户提供正式提示词前，模板状态为 `draft`，不得进入真实付费提交。

## 九、状态流

保留现有细粒度状态名称，但为新流程增加合法旁路：

```text
DRAFT
→ VALIDATING（或以持久化校验事件表达）
→ PREPARING
→ QUEUED
→ GENERATING
→ DOWNLOADING
→ VALIDATING
→ DELIVERABLE / PARTIALLY_DELIVERABLE / ACTION_REQUIRED
```

新流程不得进入：

- `ANALYZING`
- `AWAITING_CONFIRMATION`

点击“开始生成”所记录的 `paid_submission_consent_at` 取代提示词确认，但不绕过管理员配置的
全局付费开关、暂停开关、积分检查和 Provider 可用性检查。
