# 真实 API 手动验收包

日期：2026-10-08  
适用环境：正式版 `http://192.168.30.126:5173/`  
目的：在不扩大付费范围的前提下，由管理员手动完成最小真实供应商验收。

## 1. 当前边界

- G1-Core、代码测试、前端构建和数据库 readiness 已完成；
- 本文不授权真实付费调用；
- 正式版默认保持 `query-only`；
- Runner、付费提交、真实素材和供应商任务必须由管理员另行确认；
- Fake/Replay 结果不得填写为真实供应商结果。

## 3. 最小真实样本

第一次只允许：

- 1 名内部用户；
- 1 个父任务；
- 1 个视频 variant；
- 1 次真实供应商提交；
- 同画布并发 1、全局并发 1；
- 使用已批准的最短可用时长和最低可接受规格；
- 不执行批量扩容、不执行自动重试、不执行第二次提交。

图片真实 API 验收另行记录，不与视频真实提交混用预算。

## 4. 观察顺序

1. 创建任务并确认本地任务、幂等键和付费同意记录已保存。
2. 观察命令状态和 provider task ID。
3. 观察查询、下载、技术检查和最终交付。
4. 核对审计、配额预留、结算状态和用户可见结果。
5. 使用同一个幂等键重放一次，确认不产生第二次供应商提交。
6. 记录实际费用、供应商任务 ID、最终状态和人工判断。

下载失败、响应丢失、查询为空或状态不确定时：

- 不创建新幂等键；
- 不点击重新生成；
- 不释放 UNKNOWN/UNCERTAIN 费用；
- 先执行原任务查询和人工对账；
- 将结果标记为 `MANUAL_REVIEW`。

## 5. 停止条件

出现以下任一情况立即暂停付费提交：

- 重复供应商 POST；
- provider task ID 丢失或跨用户可见；
- 本地状态与供应商状态无法对应；
- UNKNOWN/UNCERTAIN 未收敛；
- 下载结果为空、损坏或无法完成技术检查；
- 配额、审计或结算记录缺失；
- 任何 P0/P1 错误；
- 实际费用超过批准上限。

## 6. 扩大范围条件

只有最小样本完成且人工确认通过后，才可以单独批准下一步：

1. 同一用户增加到 2 个 variant；
2. 增加第二个内部用户；
3. 执行小批量真实样本；
4. 建立 1 个业务日观察窗口。

每一步都必须重新记录费用上限、样本数、停止条件和结果。不能因为测试通过一次就自动解除全局付费保护。
