## 5. 前端 API 层

`frontend/src/api.ts` 是统一请求入口，当前约 402 行：

- 所有请求使用相对地址 `/api/v1/...`，由 Vite proxy 或同源部署转发。
- `request()` 统一处理超时、JSON、Cookie、开发态 `X-User-Id`、CSRF 和错误转换。
- 普通请求默认超时 30 秒，上传 60 秒，分析/确认等长任务使用更长超时。
- 写操作大多携带 `Idempotency-Key`。
- 共享认证开启时使用服务端 Session Cookie + CSRF；测试/开发态可使用 `X-User-Id`。

主要接口组：

| 领域 | 典型接口 |
| --- | --- |
| 系统/认证 | `/system/status`、`/auth/me`、`/auth/login`、`/auth/logout`、`/auth/password` |
| 素材 | `/uploads`、缩略图与资产读取 |
| 任务 | `/tasks`、`/{id}/analyze`、`/{id}/prompts`、`/{id}/confirm`、`/{id}/cancel`、`/{id}/reuse` |
| 提示词助手 | `/tasks/{id}/prompt-assistant` |
| 结果 | `/downloads/{artifactId}`、远端结果恢复、variant feedback |
| 管理 | `/admin/operations`、`/admin/users`、`/admin/credentials`、运行开关与账号管理 |
| Provider | `/admin/libtv-*`、`/admin/kling/*` |

前端典型生产流程：

```mermaid
flowchart LR
    A["上传分镜图/产品图"] --> B["POST /uploads"]
    B --> C["POST /tasks"]
    C --> D["POST /tasks/{id}/analyze"]
    D --> E["检查或修改 A/B 提示词"]
    E --> F["POST /tasks/{id}/confirm"]
    F --> G["Runner 领取并生成"]
    G --> H["下载、反馈或复用"]
```

## 8. 配置和安全边界

- 根目录 `.env` 包含真实运行配置，可能包括 API Key、Session secret、付费确认短语和 Provider 配置。交接文档没有复制这些值。
- `.env` 的默认本地运行模式与 `start-test-stack.ps1` 的测试覆盖值不同。验证网页时优先使用测试栈。
- `5173/8000` 当前属于另一目录，而且 API 报告 live/付费开关已打开；不要对它做探索性生成测试。
- 不要在提交、截图、日志或新窗口提示中粘贴 `.env`、凭据文件或 OAuth 数据。
- 真正付费生成必须单独审查 preview、运行模式、付费确认和暂停开关；不要为了 UI 验证开启这些选项。

## 9. 已知结构性注意点

- `App.tsx` 与 `styles.css` 是当前主要维护热点，修改影响面大。
- 路由是查询参数手写实现，新增页面时要同步处理初始化、`popstate`、导航状态和移动端导航。
- 页面依赖轮询，不是 WebSocket；修改任务状态展示时要考虑列表轮询和详情轮询两条路径。
- 文件上传有 4 路并发，并限制分镜图最多 7 张、产品图最多 5 张。
- 页面同时支持 LibTV 和 Kling Provider，任务创建后 Provider 固定，不应在执行中自动切换。
- 生成结果支持 A 稳定展示、B 动态广告或 A+B；不要假定每个任务永远有两个 variant。
- 当前测试数据有历史乱码标题和缺失缩略图，判断 UI 回归时要把数据问题与代码问题分开。
- `frontend/vite-ui.err.log` 保存过往开发会话错误，不代表当前 `5175` 现场；以当前浏览器 console 和 `var/test/logs/` 为准。
