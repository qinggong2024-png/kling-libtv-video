# 衣影工坊安全与调用保护方案

日期：2026-10-14  
适用范围：内部 MVP、约 5–10 名使用者、公司局域网、单机单 Worker  
状态：身份与分析/提示词风险额度 P0 已通过源码验收；共享美元预算增量已获批准，按实际 Sprint 报告确认实现范围。源码验收不代表正式运行时启用。

## 1. 目标

本方案同时解决两类风险：

1. 没有账号或没有权限的请求不能访问业务接口、任务数据或生成能力。
2. 已登录用户、脚本、重复提交和异常重试不能无限消耗 AI 或视频 Provider。

方案优先保证最大损失可控，同时不让正常生成因为等待实时报价而变慢。

## 2. 已确认的总体决策

采用“本地快速预占、后台结算、供应商硬开关”的模式：

```text
登录与权限检查
    ↓
本地额度 / 并发 / 队列检查
    ↓
数据库原子预占风险单位
    ↓
立即提交 Provider
    ↓
记录实际用量、费用或未知费用
    ↓
结算预占；未知收费继续保留风险占用
```

提交前不请求供应商报价、不调用额外 AI 估价模型，也不在 Provider 执行期间持有数据库锁。

## 3. P0：内部 MVP 立即实施

### 3.1 强制共享鉴权

- `staging` 和 `production` 必须启用会话登录。
- 生产请求不能使用 `X-User-Id` 作为身份来源。
- 开发环境的固定测试用户和自动建用户只能在明确的 `development` / `test` 环境生效。
- 启用真实 Provider 时，启动检查必须拒绝不安全的鉴权配置。
- 所有业务接口继续通过 `Actor` 获取当前用户，并按用户过滤任务、素材和输出。

### 3.2 真实 Provider 默认关闭

- `paid_submissions_paused` 默认开启。
- 图片、视频和其他真实 Provider 仅在管理员显式打开后提交。
- 保留全局暂停、Provider 暂停、用户白名单和内部试运行预算。
- 开发环境的 Fake / Replay 不得被当作生产费用保护的证明。

### 3.3 统一调用额度

以下操作都要有额度记录：

- 图片生成；
- 视频生成；
- 图片或任务分析；
- 提示词助手的 `ADVISE` 和 `REGENERATE`；
- 反馈学习等后台模型调用；
- 后续增加的导演规划、质量复核和有限自动修订。

每次调用至少记录：

- `user_id`；
- 操作类型；
- 模型和 Provider；
- 输入大小或图片数量；
- 最大输出 Token；
- 预占风险单位；
- 实际 Token、费用或 `UNKNOWN_COST`；
- 关联任务、幂等键和时间。

已有图片额度、视频额度、幂等键和未知结果语义继续复用，不另建一套互相冲突的账本。

### 3.4 风险单位规则

2026-10-14 用户批准统一美元预算。用户主界面显示美元，后台保留整数单位：

- 每个用户每日共享上限 $50，即 50,000 单位；文字、图片、视频共用该池。
- 1 单位 = $0.001，成本计算存储整数微美元，不使用浮点金额。
- 单次上限默认 $5，单批次上限默认 $10；进行中与 UNKNOWN 合计预占上限默认 $10。
- 配置独立全局硬上限；不随用户数量自动无限增加。
- Asia/Shanghai 每日零点重置；历史 UNKNOWN 不因跨日或重启自动释放。
- 原图片张数与视频 PointsReservation 限制作为现有业务约束保留，美元预算单独记录；不把点数或张数直接当美元。

```text
预计最高成本 = 本地有效价格 × 最大输入/输出/张数/秒数
             + 已授权 fallback / 重试预留
预占单位 = ceil(预计最高成本微美元 / 1000)
可用预算 = 总额度 - 已结算占用 - 处理中预占 - UNKNOWN占用
```

价格目录保存 Provider、模型、计价单位、版本、有效时间、来源及适用参数。WaveSpeed 公开起步价仅为参考；实际调用使用对应 Provider 与参数的已核实价格。参考样例见 `fixtures/wavespeed-price-reference-20261014.json`，全部标记 `reference_only`，不得直接授权付费提交。

生成前不在线询价。不支持或未配置有效价格时立即返回可读错误，或仅在存在可信最高费用依据时使用配置的保守预占；不能把任意 $5 预留当作供应商实际收费上限。离线 Fake/Replay 可用本地预占验证流程，实际费用记零，不冒充付费保护实证。

成功按可核实用量和冻结价格快照计算，释放多余预占；这是本地估算结算，不冒充供应商账单。无法确认用量或提交结果时保留 `UNKNOWN_COST` 占用。旧版抽象风险单位独立标记为历史计量，不自动重新解释成美元；历史不确定提交必须有清晰的核查处理路径。

## 4. 单次请求的行为合同

### 正常请求

1. 验证登录会话和资源归属。
2. 校验幂等键、输入大小、模型和 Provider 是否允许。
3. 在数据库中原子检查并预占额度。
4. 提交 Provider，立即释放数据库锁。
5. 保存任务状态并异步轮询结果。
6. 根据实际用量结算，或保留未知费用占用。

### 额度不足

- 立即返回明确的额度不足或暂停响应。
- 不调用 Provider。
- 不创建会造成误解的“生成中”任务。

### 超过并发或队列上限

- 返回排队状态或 `429`。
- 不通过快速重试自动绕过限制。
- 前端显示可恢复的等待或稍后重试状态。

### 超时、重试和未知结果

- Provider 已经可能接收请求时，额度继续保留。
- 未确认的提交不自动再次提交。
- 查询已提交任务与重新发起新任务分开处理。
- 同一个幂等键只能对应一次业务提交。

## 5. P1：正式对外或多人使用前补齐

- 登录失败按账号和 IP 双重限流，采用递增冷却，不永久锁死账号。
- 付费接口增加用户级请求频率、并发数和排队数限制。
- 管理员操作增加更严格的审计和二次验证。
- 正式服务使用 HTTPS，启用 Secure Cookie。
- 只开放前端入口，数据库、对象存储和 Provider 管理接口不暴露到局域网外。
- 增加异常消耗告警：单用户突增、未知费用连续出现、Provider 错误重试激增。

## 6. P2：多 Worker 或多机部署前补齐

- 将进程内限流迁移到共享 Redis 或数据库实现。
- 使用 PostgreSQL 验证跨进程的额度和并发原子性。
- 为任务执行器增加跨进程租约、恢复和重复提交演练。
- 建立供应商账户的硬额度、余额告警和自动暂停。
- 增加管理员级别的紧急停机和密钥轮换流程。

## 7. 速度和用户体验约束

本方案不要求每次生成前查询精确价格，因此正常请求只增加一次本地额度检查和预占。预占动作应保持短事务，Provider 调用不能放在事务中。

未知价格的文本请求不进入等待报价状态。有可信最高费用依据时按本地配置预占后执行；没有有效价格或安全上界时立即拒绝并提示配置缺失。额度、并发、Provider 暂停或安全检查失败时同样直接反馈。

## 8. 验收标准

- 未登录请求不能读取任务、素材、输出或调用生成接口。
- 伪造 `X-User-Id` 不能改变当前身份。
- 生产环境不会自动创建开发用户。
- 并发提交不能突破单用户和全局额度。
- 相同幂等键不会产生重复 Provider 提交。
- 额度不足时 Provider 调用次数为零。
- 重启后已预占、已消费和未知费用仍可对账。
- 未知价格的文本请求不会等待报价；缺少有效价格时立即反馈，不调用 Provider。
- Provider 超时或 UNKNOWN 不会被自动重复收费提交。
- 管理员可暂停新付费提交，同时保留已提交任务查询和对账。

## 9. 明确不采用的做法

- 不在每次请求前调用模型或供应商接口估价。
- 不把精确人民币费用作为未知价格请求的前置条件。
- 不在 Provider 调用期间持有数据库锁。
- 不把前端按钮禁用当作后端安全措施。
- 不为了内部 MVP 引入微服务、独立计费平台或复杂 Agent 集群。

## 10. 实施顺序

1. 强制共享环境会话鉴权，封闭开发身份和生产配置混用。
2. 将分析和提示词助手接入统一风险额度。
3. 增加用户级并发、队列和登录限流。
4. 增加 HTTPS、异常告警和供应商硬额度。
5. 在多 Worker 或公网开放前完成 PostgreSQL 并发和恢复验证。

本方案只定义工程实施方向，不代表已经上线、已经启用真实付费 Provider，或已经获得生产部署授权。
