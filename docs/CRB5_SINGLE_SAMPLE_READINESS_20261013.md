## 2. 单样本范围

| 项目 | 冻结范围 |
| --- | --- |
| 商品 | 单 owner、单 `Product.id`、单真实 SKU、单已确认 `ProductVersion.id` |
| 工件 | 单不可变 package/revision，镜头仅 `FIRST_FRAME` |
| 动作 | 单次初始 `image_edit`，一个明确 Provider/model，单输出目标 |
| 来源 | 已登记原商品正面图及该请求明确许可的输入；角色、顺序和字节哈希冻结 |
| 请求 | 一个精确 request/evidence hash、一个幂等身份、一次人工授权 |
| 结果 | 回收至既有图片生产真源，技术成功、像素复核、人审资格、交付批准分别验收 |

明确排除：`SHOT_01`、多镜、批量、视频或 `director_fixed` 实产、自动 Critic 付费调用、自动真实性修订、备用 Provider 自动切换、失败自动重投和追加生成。额外分析/规划/复核调用不包含在本次授权内；如必需，另行评审并计入预算。

一张样本只证明该 SKU、package、Provider/model 和环境下的该次结果，不证明所有商品质量提升、视频交付能力或完整 `PRODUCTION_READY`。

## 4. Provider、模型和输入输出合同

Provider/model 不在本文件猜测或默认指定。技术负责人核实能力和 adapter 映射，业务/素材负责人核实输入许可，QA 固定待执行用例。

| 合同项 | 确认要求 |
| --- | --- |
| Provider/model | 精确名称/ID、版本或能力快照、`image_edit` 支持、远端查询及账单证据能力 |
| 输入角色 | 原商品正面图为商品事实来源；其他输入仅在 manifest 中显式获准时加入 |
| 输入顺序 | 保存 role、order、adapter field 和 hash；不得把 Fake 首帧充当真实商品或合格参考 |
| 媒体规格 | 输入数量、格式、大小、分辨率、比例和 Provider 限制逐项确认 |
| Prompt | 冻结生产包 Prompt/Preservation；提交时不重新规划或注入学习内容 |
| 输出规格 | 单输出目标、格式、分辨率、比例、字节限制、下载时限和对象保留要求 |
| 外部副作用 | 素材上传是否计费、是否产生不可撤销副作用、POST 是否支持幂等及查询，均须确认 |
| 回执 | Provider task ID、提交结论、状态、响应摘要、费用/quote 证据可关联到原 ticket |

不支持必需角色或输出规格、许可不足、能力无法证实或请求指纹不一致时关闭执行，不自动降级到另一 model。

管理员必须提供实际 live/暂停开关位置、默认关闭证据、仅限本次任务的开启范围、权限、审计、到期关闭和紧急关闭方式。开关存在与可操作性必须验证，不编造新 endpoint、环境变量或控制台按钮。

提交前再次核对版本、许可、预算、停止/撤销及环境。提交后关闭开关只阻止新请求；已发生的调用继续只读查询、回收和对账，不伪装为从未提交。

## 7. 账本真源与 UNKNOWN 对账

真实账本关系尚未决定。必须人工选择并确认以下方案之一，不新建第二套账本：

- 复用 `ImageQuotaReservation` 作为图片额度真源，并批准费用记录的关联合同。
- 经批准统一到既有 `PointsReservation/PointsLedger`，明确图片单位、点数、币种及费用映射。
- 使用另一个已经批准的账本服务，并提供幂等预占、结算和审计合同。

选择由技术、财务/账本及业务负责人共同签字。ticket/lease/batch/item/attempt/账本的持久关联、原子预占和一次结算必须有证据；本文件不新增关系、字段、迁移或 reconcile API。

| 结论 | 后续规则与证据要求 |
| --- | --- |
| 明确预提交失败 | 确认无外部提交及费用后，按批准规则一次释放；保留原失败证据 |
| 已提交且有 task ID | 只查询原任务并回收；费用按回执/账单和已批准政策结算一次 |
| `UNKNOWN/WRITE_UNCERTAIN` 无 task ID | 保留未知 attempt/ticket 和费用证据，冻结新执行，禁止自动 POST/重试/释放 |
| 人工确认已提交 | 记录 Provider 查询/后台/账单证据和核验人，绑定原任务后继续查询与对账 |
| 人工确认未提交 | 记录独立可核验证据，按批准规则结算/释放；旧票据不可复活，不自动新建请求 |
| 仍无法判定 | 持续未知/阻塞，指定对账责任人和复查期限，不显示成功或资格 |

Provider 成功但输出下载/写入失败时，只恢复查询和物化，不重新生成。Provider 失败是否收费、UNKNOWN 占用多久、退款及人工调整规则必须由财务明确；执行窗口不得自行决定。Creative 离线 `reconcile_not_submitted` 通过不证明远端真实账单已经对清。

## 8. 输出物化、像素与交付门

| 门 | 必须提供的证据 | 不可替代的下一门 |
| --- | --- | --- |
| 提交确认 | 原 ticket、幂等键、Provider/model、task ID、响应摘要及费用状态 | 不等于生成成功 |
| 技术完成 | 原任务终态、输出 URL、下载结果、媒体类型、尺寸、字节大小、SHA-256、持久 object key | 不等于像素质量合格 |
| 来源映射 | 原 package/revision、`FIRST_FRAME`、candidate、batch/item/output、hash 一致性 | 不等于人工选择或审核 |
| 像素复核 | 原商品与输出真实像素可查看；逐项检查并记录缺陷、区域、结论及审查人 | AI pass 不写人工资格 |
| `QUALIFIED` | 有权限人工逐候选审核，理由、时间、资格范围和许可均有效 | 选择图片不等于资格；资格不等于交付 |
| `Deliverable` | 单独最终批准，费用已对清、来源可追溯、许可和保留有效、可下载且 hash 一致 | 不授权视频或批量生产 |

像素复核至少覆盖版型、颜色、图案/Logo/文字位置、衣料与受力、人体/手部、人物行为、空间几何/光照、构图、卖点以及 UGC 真实性；依据锁定合同标注通过、失败、N/A 或 unverified。未知背面不冒充实物事实，`USER_ASSUMED` 必须保留对应资格范围。

缺原图/输出像素、hash 不一致、下载或 object 写入失败、许可撤回、审查未完成、账务未知时，不授予正式资格或交付。人工审核必须走已确认的既有入口；缺少接口则另立边界评审，不用手工改库代替。

## 9. 最终验证步骤与失败矩阵

先完成准备表和未闭合接线的独立评审，再完成 testing/main 隔离回归、实际环境核验和精确请求批准。真实样本只在这些步骤之后执行一次；执行前保存授权/manifest/请求指纹，执行后保存回执、物化、像素、账务及签字证据。

以下用例是待执行标准，空白检查和历史 Fake PASS 不表示这些场景已通过：

| 场景 | 必须验收的行为 | 当前证据状态 |
| --- | --- | --- |
| 重复请求/同键重放 | 复用原记录，不重复 claim、上传、POST 或预占 | 真实链待验 |
| 同键不同 hash/版本过期 | 拒绝新副作用，保留原请求证据 | 真实链待验 |
| owner 越权/许可缺失/素材撤回 | 提交前拒绝；已提交保留对账，不撤销事实 | 真实链待验 |
| stop/授权撤销/live 关闭 | 阻断新执行，保留 append-only 审计 | 真实链待验 |
| 明确失败/quote 过期/预算不足 | 不追加调用，按已确认账务规则处理 | 真实链待验 |
| 超时/连接断开/`WRITE_UNCERTAIN` | 进入未知，不宣称失败未提交，不自动重投 | 真实链待验 |
| 有 ID 的 UNKNOWN | 只查询原 Provider task；状态与账单对齐 | 真实链待验 |
| 无 ID 的 UNKNOWN | 人工/服务端对账，证据未明确前阻塞 | 真实链待验 |
| 下载/对象写入失败/hash 异常 | 可恢复物化，拒绝资格，不重新付费生成 | 真实链待验 |
| claim 后/回执保存前进程中断 | 从持久证据恢复；不以重启解除未知或次数限制 | 未证明真实崩溃窗口 |
| 人审拒绝/资格撤回 | 保留理由和原输出，阻断交付及后续生产 | 真实链待验 |

真实故障注入若可能额外付费、写生产数据或重启服务，另行批准；不可为补证据擅自扩大单样本范围。

内部 MVP 可按既有 5-10 人内网、单机单 worker 策略记录 PostgreSQL 多 worker、完整灾备和穷举崩溃测试的未覆盖项；不能宣称已经证明。CRB-2 报告更严格的生产级门槛不能由本文件自动豁免，适用标准及任何例外必须由人工接受。幂等、权限、UNKNOWN、预算、人审及交付硬门不豁免。

## 10. 暂停与回滚

1. 任一授权/来源/预算/状态异常立即停止新执行，管理员关闭本次 live 并记录时间、原因和操作人。
2. 提交前撤销授权和 lease，按已批准规则释放确实未提交的预占；保留不可变记录。
3. 提交后或结果未知时保留 ticket、lease manifest、batch/item/attempt、Provider/账单证据，只查询、回收和对账，不自动再次 POST。
4. 撤回资格/交付入口，隔离不合格或未核验输出；对象保留和清理依据批准政策，不在本轮删除。
5. 若后续代码接线需回滚，仅由发布负责人执行已批准源版本回退；不回滚账本事实、不覆盖其他窗口修改、不执行未批准迁移或服务重启。
6. 恢复必须重新核验原因、版本/许可/预算/未知账务并重新授权；关闭开关不代表退款、撤销外部任务或完成对账。
