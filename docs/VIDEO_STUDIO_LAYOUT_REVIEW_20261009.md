# Video Studio 布局决策修订

日期：2026-10-09
范围：Checkpoint 1 再次返工，仅 Video Studio 与复用组件
状态：待人工方向验收；替代 20261008 的当前布局方案

## 输入证据

用户明确指出“分镜序列可以在上传分镜那里进行排序”，并继续否定布局。
此前方案把上传放在窄侧栏，把顺序确认放在右侧主生产区，仍将同一个素材准备任务拆散。
工程测试证明可操作，不证明操作分组正确，更不证明视觉获得认可。

## 任务重要性与空间分配

按依赖、错误后果、操作关联和持续可见性定性评定，不虚构数值权重：

| 任务 | 依据 | 呈现方式 |
| --- | --- | --- |
| 上传、排序、删除 | 同一批输入的连续操作，排序直接影响生成 | 上传区内唯一可编辑网格 |
| 可选一致性主体 | 是参考输入，不是生成参数 | 素材区内，位于分镜之后 |
| 模板、生成方式、创意意图 | 决定生成目标，与素材互相约束 | 右侧生成配置区，可与素材对照 |
| 完整配方、高级参数 | 专项核查，不是每次必经操作 | Drawer / 折叠 |
| 源图大图与缩放 | 单张质量核查，需要时才打开 | 从上传区进入检查浮层并返回 |
| 时长、结果数、付费提交 | 依赖两区准备完成，存在付费后果 | 两区之后的统一提交行 |
| 生成状态、结果审核 | 分属等待和输出决策阶段 | 提交之后，保留真实状态和审批边界 |

素材区略宽不是“素材预览权重最高”：其空间服务上传和多图排序，不放永久大图。桌面两区网格为 1.15:1，素材区还扣除分隔留白；这只是当前实现约束，不是经业务研究验证的权重。

## 方案取舍

1. 仅把旧横向分镜条移到窄侧栏：不采用，多图编辑仍拥挤。
2. 合并上传和排序，使用素材准备 / 生成配置两个工作区：本轮采用；操作归属清楚，保留同时对照。
3. 固定大画布、三栏预览、强制分步向导：本轮不采用，没有相应编辑能力或实测收益。

```text
上传 / 排序 / 删除 / 可选主体
→ 模板 / 生成方式 / 创意意图
→ 时长 / 数量 / 明确付费提交
→ 阶段 / 异常
→ 成品 / 人工审核
```

允许先选模板，不强制步骤锁定。素材排序不再要求跨栏。完整模板配方与单图检查是返回原操作点的支线。

## 布局约束

- 空状态只有上传入口，无独立“分镜序列”标题和占位。
- 每张源图仅一份缩略表示；七张图换行，不使用横向滚动条组织排序。
- 默认配置不重复模板名称、描述和版本块；真实状态、画幅和数量限制保留。
- 低于 800px 按素材、配置、提交、反馈顺序纵向排列，保持 DOM 顺序。
- 提交在两区之后；仅对桌面两张图场景要求首屏可见，不声称七图或移动端均无需滚动。
- 素材和配置区不是嵌套卡片，不保留上传区旧 hover 阴影。
- 不更改 API、计费、幂等、UNKNOWN 锁、批量恢复、来源 ID 或审批合同。
- 标准图片转视频表单保留原布局及完整 TemplateCard，不强制套用 Studio。

## 验收边界

自动化检查上传区归属、空占位、七图换行、拖拽与键盘排序、删除目标、大图/缩放/焦点、模板配方、主流程及异常恢复；检查 1440、1102、1024、768、390px 截图与几何。

人工仍需确认真实服装素材是否易比较、多图和移动端是否顺手，以及与旧版相比的点击、耗时和错误率。没有访谈、真实业务频率或计时对照，本轮不能声称完成正式产品研究、改善某百分比效率或可以上线。
