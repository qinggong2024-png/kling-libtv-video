# 正式版与测试版隔离

| 环境 | 代码 | Web | API | 数据与素材 |
| --- | --- | --- | --- | --- |
| 正式版 | `libtv自动化生成` 前端 + `libtv-production` API/Runner | `http://192.168.30.126:5178/` | `8000` | `libtv-production` 工作树内的 `var` |
| 测试版 Safe | `C:\Users\Reel\Documents\libtv自动化生成` 的 `codex/testing` | `5175` | `8001` | `var\test` |
| 测试版 Full | `C:\Users\Reel\Documents\libtv自动化生成` 的 `codex/testing` | `5175` | `8001` | `var\test-live` |

正式后端与 Runner 使用 `libtv-production`；发布确认只认 `5178` 入口。功能开发和 Codex 验证使用测试端口，不能把测试端口当作正式入口。

> 正式版唯一 Web 入口是 `http://192.168.30.126:5178/`。`5173` 不是正式版地址，不能用于发布确认或交付。

启动零费用测试版（模拟 Provider，但包含独立 Runner，可跑完整调度流程）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start-test-stack.ps1
```

启动真实 Provider 全链路测试版（会产生真实 API 费用）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start-test-stack.ps1 -Profile Full
```

两个测试 Profile 都会启动同一工作树内的前端、API 和 Runner，并使用独立且持久的数据库、素材目录、Cookie、运行配置和日志。`Full` 首次启动会把本机已加密的 Kling 配置复制到 `var\test-live\runtime`；之后测试版和正式版分别维护自己的运行配置。

验证通过后，提交 `codex/testing` 的代码并合并到 `main`，再从正式工作树重启正式服务。代码推广不会复制或清空任何 `var` 目录，因此：

- 测试任务和生成结果继续保留在 `var\test` 或 `var\test-live`；
- 正式版已有任务和生成结果继续保留在正式工作树的 `var`；
- 正式版得到的是测试通过的同一份代码，不会用测试数据库覆盖正式数据库。
