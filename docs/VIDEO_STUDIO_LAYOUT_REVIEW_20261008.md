# Video Studio 布局决策与验收

日期：2026-10-08
范围：Checkpoint 1 布局修订，不扩展其他工作区

## 当前问题

上一版中央画布只展示上传源图，提供缩放和大图，不支持构图、镜头、动作或时间线编辑。它与源素材缩略图、分镜缩略图重复表达同一输入。中央区域使用 1.8fr，而模板/配置仅 1fr；空媒体舞台也预留 280–360px 高度。这是将“Canvas 优先”误解为“固定源图预览最大”。

此前的 build、lint、组件和浏览器流程验证只能证明工程行为，不能证明任务权重、布局动线或易用性合理。没有访谈、真实用户操作耗时或业务频率统计，不应声称已经完成正式产品研究。

## 任务评定

按“是否阻塞下一步、使用频率假设、错误影响、是否需要持续可见”做定性判断。不提供虚构数值权重；下表是待人工验证的设计假设。

| 阶段 | 任务 | 优先级依据 | 默认呈现 |
| --- | --- | --- | --- |
| 配置 | 添加分镜、确认主体 | 分镜是必需输入；主体可选，但影响一致性与参考数量 | 紧凑输入侧栏 |
| 配置 | 模板、生成方式、创意 | 决定生成意图，错误会造成无效或付费失败 | 主生产区 |
| 配置 | 确认顺序、删除错误图 | 直接影响输出；必须支持键盘与拖拽 | 唯一分镜缩略序列 |
| 配置 | 时长、结果数、付费提交 | 完成任务的主动作；保留费用确认与无效输入保护 | 紧随分镜的提交区 |
| 配置 | 放大检查单张源图 | 质量检查重要，但不是持续操作或必经步骤 | 点击缩略图后打开检查浮层 |
| 生成 | 阶段、异常、未知提交 | 决定等待、处理或停止，禁止盲目重付费 | 队列、阶段和就地错误 |
| 审核 | 查看、播放、比较成品 | 质量决策对象是输出，不是输入放大图 | 结果区与详情/播放浮层 |
| 全程 | 技术参数与完整配方 | 专项决策需要，但不应阻塞基础操作 | 高级折叠与配方抽屉 |

## 方案取舍

1. 仅缩小原三栏画布：不采用，仍存在重复素材和跨栏来回检查。
2. 输入侧栏 + 主生产区：采用；桌面左侧负责输入，右侧连续完成意图、顺序与提交。
3. 分步向导：暂不采用；会强制切页并增加批量重复配置的操作，当前没有用户研究支持。

主路径：

```text
添加分镜 / 可选主体
→ 模板 + 创意配置
→ 分镜顺序确认
→ 时长 + 结果数 + 明确付费提交
→ 阶段 / 异常
→ 成品检查 / 人工审核
```

源图检查是从分镜进入再返回的支线。缩放、大图、Escape 和焦点恢复保留；不再默认占据主流程。模板在前、分镜在后便于对照模板数量要求；先检查模板再上传也允许，没有强制步骤锁定。

## 布局约束

- 桌面输入栏 288px，主生产区使用剩余空间；1024px 时输入栏收为 248px。
- 右侧模板/创意并列，分镜和提交在下方连续排列，不创建新的参数墙或统计区。
- 768px 以下使用与 DOM 一致的纵向顺序；390px 模板与创意也纵向排列。
- 每个分镜默认仅有一份缩略表示；源图检查仅在打开浮层时放大。
- 空分镜不预留大画布；结果仍保留真实审核和交付语义。
- 不自动切换到结果、跳转编辑或在付费提交后假装完成审核。

## 验收与边界

自动化验证：

- 1440×900 配置两张图和历史主体后，提交按钮在首屏内；记录实际坐标而非凭截图推断。
- 1440、1024、768、390 四视口无页面横向溢出。
- 两张图默认恰有两张分镜缩略表示，没有永久源图画布。
- 分镜支持键盘前后移动、拖拽、删除、检查浮层、缩放和嵌套大图。
- 未知提交、进行中、批量模式保持变更保护；批量部分成功不重建成功组。
- 检查关闭后恢复原分镜焦点；任务抽屉、结果播放和深链接刷新继续工作。

人工验证尚待执行：

- 新员工五分钟上手与三分钟完成配置。
- 与旧版相同素材/相同模板对照操作耗时、错误率与点击次数。
- 真实服装素材与不同分镜数量是否易于检查、批量进口命名是否易于理解。
- 主生产区与结果区的优先级是否符合实际团队使用习惯。

本轮不声称减少了某百分比点击或提升了某百分比生产效率。测试桩结果不是真实 Provider 质量证据。工程门禁和源码同步也不等于人工方向验收、上线批准或部署。
