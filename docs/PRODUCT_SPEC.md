版本：V1.0

状态：产品范围冻结，作为前端开发与验收的上位约束

2026-10-13 研发方向调整：当前目标为 Creative OS Core + Human Production Loop。
执行顺序及冻结边界见 `CREATIVE_CORE_HUMAN_LOOP_20261013.md`；保留四工作区、
既有质量门和人工接受要求，不再继续扩展完整 Creative OS。

本次冻结阶段只固化规范和审查记录，不代表页面已完成。后续实际开发首先执行 Video Studio + Design System。

2026-10-10 增量合同：Creative Workflow 的已确认开发规则见 `CREATIVE_WORKFLOW_IMPLEMENTATION_20261010.md`，仅定义待实现能力，不代表现有模式已改变或 Checkpoint 1 已接受。智能导演作为 Image Studio 内模式；不新增第五个产品工作区。

## 1. 产品定位

```text
AI Creative Production Tool
for Cross-border Fashion Ads
```

衣影工坊服务跨境服装广告团队，帮助素材制作人员完成：

```text
产品图 / 源素材
→ AI 图片生成
→ AI 视频生成
→ 审核
→ 素材交付
```

产品首先是生产工具，不是 Dashboard、CRM 或 ERP。

## 2. 用户与核心任务

主要用户是负责商品广告素材生产、审核和交付的一线创意人员。

核心任务：

1. 选择产品、人物、场景或其他已登记素材。
2. 选择符合生产目标的模板或配方。
3. 在画布和面板中完成必要的创意配置。
4. 创建图片或视频生产任务。
5. 感知准备、生成、校验和完成状态。
6. 查看、比较、审核结果。
7. 将合格素材交付或继续进入下一生产阶段。

## 3. 冻结范围

第一版只包含四个产品工作区：

| 产品路由 | 用途 | V1 边界 |
| --- | --- | --- |
| `/studio/image` | 图片生产 | 产品、人物、场景选择，图片生成、选择与转视频 |
| `/studio/video` | 视频生产 | 素材、模板、画布、分镜、生成与结果查看 |
| `/tasks` | 任务中心 | 任务状态、详情、重试、审核与结果 |
| `/library` | 素材库 | Character、Product、Scene、Template 管理与选择 |

现有仓库的导航仍使用 `?view=images|make|records|library` 兼容入口。产品路由语义先冻结；真正 URL 路由迁移单独作为开发任务，不得在页面开发中偷偷改变既有深链接和返回行为。

既有认证、管理和设置入口作为运营支撑保留，不新增业务页面，不因“四页面范围冻结”删除现有权限或 Provider 配置能力。

## 4. 业务主线

```text
Product / Source Assets
↓
Image Generation / Candidate Assets
↓
Per-asset Quality Decision
↓
Qualified Assets Only
↓
Video Generation
↓
Review / Final Approval
↓
Export / Deliverable
```

基础设施能力服务于主线，不得取代主线：

```text
Job / Queue / Retry / Recovery / Download / State / Traceability
```

`Generated`、`Technically Valid`、`Quality Checked`、`Approved` 和 `Deliverable` 必须保持语义区分。前端可以提供简化展示，但不能把技术成功直接显示为正式交付。

### Creative Workflow 待实现扩展

- 商品正面即可分析并提取 DNA；背面/详情可选。分镜前提示补背面，缺背面可确认按衣身底色、无印花纯色处理，记录用户假设，不冒充实物背面事实。
- 人工选择品牌或通用风格，优先于模型/站点推断；从已有内容库读取品牌风格、人物/表演设定和兼容动作，保存真实来源与内容快照。
- 导演输出版本化图片、分镜和视频 Prompt；选方向不触发生成，首帧、指定分镜和视频分别授权。图片阶段可额外确认有界真实性修订范围，不默认授权无限追加。
- 首帧审核选择与最终分镜审核选择分别保存；选择不等于 QUALIFIED，只有合格分镜可进入视频。
- 视频自定义模式是可编辑 Prompt 的生视频工具；新自动模式以显式 director_fixed 执行导演已确认生产包，不再次自动规划或注入学习指导。
- 视频由服务端拉取先前上传的产品图和已审核分镜，不重复要求用户上传；素材权限、哈希、保留与 Provider 数量限制仍生效。
- 保留旧客户端显式兼容与历史任务查询/恢复，不将新自动模式语义套用到已提交任务。工程同步不等于上线。
- 进入 CW-1 前先通过 CW-0.5 的八项前置评审：能力/素材、状态恢复、预算授权、DNA/Prompt 真源、使用许可、迁移兼容和质量/收益基线。前置项已列出，尚未通过。
- 吸收用户生图插件 v1.13.5：商品/品牌硬锁、A/B/C 实质差异、Character/Scene 分层、常开六维 Reality、参考污染与输入证据、紧凑 Prompt/Preservation、分镜构图/对白连续性和逐项像素复核。
- 固定执行 Product→方向候选→人工选择→锁定 DNA/Reality/参考安全→脚本/文字分镜/Prompt/生产包→授权→绑定/生成/技术校验/像素复核。身份锁定不是表情冻结，未知背面不补造；真实参考展示不等于 Provider 接收。
- 本项目允许服务端自主真实性循环，插件的会话宿主限制不照搬。首版默认关闭；启用需确认每初稿默认 1 次、硬上限 2 次定向修订和总费用上限；按失败证据回对应模块、追加新包/候选，未知提交/费用、缺像素、超限或锁项冲突停止。所有模型调用计入预算。
- 真实性批评器复用已批准且支持真实像素输入的模型能力，未证实能力时禁用自动修订、保留人工审核；不建设独立自动评分平台。AI pass 不写 QUALIFIED，人工审核和视频最终批准不被循环替代。
- 背面 evidence_status 与 qualification_scope、Prompt Registry 不可变版本及真实/拟提交 Prompt、shot_id 来源映射、循环记录独立持久化。USER_ASSUMED 可按确认合同生产，但不能标实物背面已核验。
- 以首帧/分镜合格率、真实性缺陷、人工耗时、重复操作、总成本、迭代次数/停止原因衡量收益；静态规则、真实输入、像素审查和质量对照分别验收，不保证每图必然改善。

## 5. 产品原则

### 工具优先

每个功能必须至少满足以下一项：

- 提高生产效率；
- 降低人工操作；
- 提高素材质量。

三项均不满足的功能不进入 V1。

### Canvas 优先

页面的视觉中心是素材、画布、分镜或结果，而不是统计卡片、表格或参数墙。

“Canvas 优先”不要求静态源图预览永久占据最大区域。空间与可见性按当前任务阶段分配：配置时以必要输入、模板、分镜和提交为中心；生成时以阶段与异常为中心；审核时以成品为中心。只具备缩放/放大的源图检查应按需打开。Video Studio 当前布局依据见 `VIDEO_STUDIO_LAYOUT_REVIEW_20261009.md`，20261008 记录保留为历史；未经真实用户测量不得声称权重已得到业务验证。

上传、排序、删除与单图检查属于同一个素材准备任务，必须在上传区内完成，不另设独立分镜序列区。当前改为纵向素材整理、创意配置、统一提交三个操作区，不再左右分割输入和表单。可选一致性主体默认收起，已有种子参考图时展开；收起保留输入和摘要。空上传区不预留分镜占位，七张图按宽度排列或换行，不要求横向滚动才能编辑。模板只显示当前选择、状态和关键限制，完整配方按需打开。当前修订依据见 `VIDEO_STUDIO_BANDS_REVIEW_20261009.md`。

### 渐进披露

常用操作默认可见；高级参数默认折叠；不要求用户先理解完整技术配置。

### 面板优先

编辑和查看详情优先使用 Drawer、Panel 或局部工作区，不因为打开详情而丢失当前生产上下文。

### 证据优先

状态、审核、失败和交付信息必须来自真实 API 或持久化状态。不得使用假数据、猜测的费用或视觉上看似完成的占位状态冒充生产结果。

## 6. 角色边界

Codex 可以自主完成：

- 任务拆解和开发排序；
- 组件和页面实现；
- 测试、浏览器验收和代码审查；
- 低风险缺陷修复；
- 文档和 Sprint Report 更新。

必须保留人工判断：

- 产品方向是否正确；
- 商业优先级；
- 最终视觉和易用性是否达标；
- 是否允许上线或扩大真实生产。

人工检查点：

1. Video Studio + Design System 完成后确认方向。
2. 四个产品工作区完成后确认可以上线。

## 7. 非目标

V1 不建设：

- 通用 Dashboard、CRM、ERP；
- 完整 QA / Benchmark / Annotation 平台；
- 未被真实生产证据触发的 VLM、VTON、动态 Provider 路由；
- 与生产主线无关的高级数据分析；
- 为了“架构漂亮”而重写已有可靠后端流程；
- 任何会绕过现有幂等、审核、交付和权限语义的前端快捷路径。

## 8. 完成定义

一个页面只有同时满足以下条件才算完成：

- 核心生产流程可操作；
- 真实状态可感知；
- 错误和空状态可处理；
- 关键操作可键盘访问；
- Drawer / 返回 / 深链接行为不丢失上下文；
- 复用现有共享组件和 API 类型；
- `npm run build`、`npm run lint`、相关测试通过；
- 在目标桌面和移动视口完成浏览器验收。

产品人工验收另行记录：

- 新员工在 5 分钟内理解并完成基础操作；
- 在 3 分钟内完成素材选择到提交任务的人工操作，不把 Provider 等待时间算作可保证的 3 分钟；
- 对照现有流程测量点击和人工耗时，而不是凭页面观感宣称改善；
- 支持现有 API 允许的批量生产，且保持逐项结果与部分失败可追踪。

以上是验收目标，不是本次已验证的结果。商业优先级和最终易用性仍由产品负责人确认。
